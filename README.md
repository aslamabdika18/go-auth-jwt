# Go JWT Authentication

Simple JWT authentication API built with Go, Gin, PostgreSQL, and pgx.

## Features

- User registration
- Request validation
- Password hashing with bcrypt
- User login
- JWT authentication
- JWT stored in HttpOnly cookie
- Protected route middleware
- Get current authenticated user
- Logout
- PostgreSQL database
- Database migrations with golang-migrate

## Tech Stack

- Go
- Gin
- PostgreSQL
- pgx
- golang-jwt/jwt
- golang-migrate
- go-playground/validator
- bcrypt

### Architecture Overview

This project follows a simple layered architecture. Each layer has a specific responsibility:

```text
HTTP Request
     ↓
Router
     ↓
Middleware
     ↓
Handler
     ↓
Service
     ↓
Repository
     ↓
PostgreSQL
```

The response flows back through the application:

```text
PostgreSQL
     ↓
Repository
     ↓
Service
     ↓
Handler
     ↓
HTTP Response
```

### `main.go`

The application entry point.

Responsibilities:

- Load environment configuration.
- Configure Gin mode.
- Run database migrations.
- Connect to PostgreSQL.
- Initialize dependencies.
- Create repositories, services, and handlers.
- Initialize the router.
- Start the HTTP server.

### `internal/`

Contains application code that should only be imported by code inside this project.

The `internal` directory is a special convention supported by Go. Packages inside it cannot be imported by unrelated external projects.

---

### `internal/auth/`

Contains authentication-related logic.

#### `jwt.go`

Responsible for JWT operations:

- Generate access tokens.
- Set token claims.
- Configure token expiration.
- Validate access tokens.
- Extract the authenticated user ID from the token.

#### `password.go`

Responsible for password security:

- Hash passwords using bcrypt.
- Compare plain passwords with stored password hashes.

The user module does not implement hashing logic directly. Authentication concerns are isolated in this package.

---

### `internal/config/`

Contains application configuration.

#### `config.go`

Responsible for:

- Loading environment variables from `.env`.
- Mapping environment variables into the `Config` struct.
- Validating required configuration values.

Example configuration:

```text
APP_PORT
DB_HOST
DB_PORT
DB_NAME
JWT_SECRET
JWT_ACCESS_TOKEN_TTL
```

Other parts of the application receive configuration through the `Config` struct instead of repeatedly calling `os.Getenv()`.

---

### `internal/database/`

Contains database connection and migration logic.

#### `postgres.go`

Responsible for:

- Building the PostgreSQL connection string.
- Creating the `pgxpool.Pool`.
- Verifying the database connection.

The application uses `pgxpool` for PostgreSQL connection pooling.

#### `migrate.go`

Responsible for running database migrations when the application starts.

Migration files are embedded into the application using Go's `embed` package.

#### `migrations/`

Contains SQL database migrations.

Each migration has two files:

```text
*.up.sql
```

Applied when migrating forward.

```text
*.down.sql
```

Used to reverse the migration.

Example:

```text
000001_create_users.up.sql
000001_create_users.down.sql
```

---

### `internal/middleware/`

Contains HTTP middleware.

#### `auth.go`

Responsible for protecting authenticated routes.

Authentication flow:

```text
HTTP Request
     ↓
Read access_token from HttpOnly Cookie
     ↓
Validate JWT
     ↓
Extract user ID
     ↓
Store user ID in Gin Context
     ↓
Continue to Handler
```

If the token is missing, invalid, or expired, the middleware returns:

```text
401 Unauthorized
```

---

### `internal/router/`

Contains HTTP route definitions.

#### `route.go`

Responsible for:

- Creating the Gin router.
- Defining API route groups.
- Registering public routes.
- Registering protected routes.
- Attaching middleware to protected endpoints.

Current API structure:

```text
/health

/api/v1/auth/register
/api/v1/auth/login
/api/v1/auth/logout
/api/v1/auth/me
```

---

### `internal/user/`

Contains all user-related functionality.

This module follows the following flow:

```text
Request
   ↓
Handler
   ↓
Service
   ↓
Repository
   ↓
Database
```

#### `model.go`

Contains user-related data structures.

Examples:

- `User`
- `RegisterRequest`
- `LoginRequest`
- `Response`
- `LoginResponse`

Request and response models are separated to prevent sensitive fields such as password hashes from being returned to the client.

#### `handler.go`

Responsible for the HTTP layer.

Responsibilities include:

- Parsing JSON requests.
- Request validation.
- Calling the service layer.
- Mapping errors to HTTP status codes.
- Returning JSON responses.
- Setting and clearing authentication cookies.

Examples:

```text
POST /register
POST /login
GET  /me
POST /logout
```

The handler should not contain database queries or business logic.

#### `service.go`

Contains application and business logic.

Responsibilities include:

- Normalizing user input.
- Coordinating authentication logic.
- Hashing passwords.
- Verifying login credentials.
- Generating JWT access tokens.
- Coordinating repository operations.

The service sits between the HTTP layer and the database layer.

#### `repository.go`

Responsible for database access.

Responsibilities include:

- Creating users.
- Finding users by email.
- Finding users by ID.
- Translating database-specific errors when necessary.

Database queries are kept out of handlers and services.

---

## Request Flow Example

### Register

```text
POST /api/v1/auth/register
          ↓
       Router
          ↓
       Handler
          ↓
Validate request
          ↓
       Service
          ↓
Hash password
          ↓
     Repository
          ↓
     PostgreSQL
          ↓
    User created
          ↓
    HTTP 201 Created
```

### Login

```text
POST /api/v1/auth/login
          ↓
       Router
          ↓
       Handler
          ↓
       Service
          ↓
Find user by email
          ↓
Compare password
          ↓
Generate JWT
          ↓
Set HttpOnly Cookie
          ↓
    HTTP 200 OK
```

### Authenticated Request

```text
GET /api/v1/auth/me
          ↓
       Router
          ↓
   Auth Middleware
          ↓
Read JWT from Cookie
          ↓
Validate JWT
          ↓
Extract User ID
          ↓
       Handler
          ↓
       Service
          ↓
     Repository
          ↓
     PostgreSQL
          ↓
    HTTP 200 OK
```

## Getting Started

### 1. Clone the repository

```bash
git clone https://github.com/aslamabdika18/go-auth-jwt.git
cd go-auth-jwt
```

### 2. Create environment file

```bash
cp .env.example .env
```

Update the `.env` values according to your local environment.

### 3. Install dependencies

```bash
go mod download
```

### 4. Run PostgreSQL

Make sure PostgreSQL is running and the database configured in `.env` exists.

### 5. Run the application

```bash
go run .
```

Or, if using Air:

```bash
air
```

## Environment Variables

```env
APP_NAME=go-auth-jwt
APP_ENV=development
APP_PORT=8080

DB_HOST=localhost
DB_PORT=5432
DB_NAME=go_auth_jwt
DB_USER=postgres
DB_PASSWORD=your_database_password
DB_SSLMODE=disable

JWT_SECRET=replace_with_a_long_random_secret
JWT_ACCESS_TOKEN_TTL=15
```

`JWT_ACCESS_TOKEN_TTL` is measured in minutes.

## API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| GET | `/health` | Health check |
| POST | `/api/v1/auth/register` | Register a new user |
| POST | `/api/v1/auth/login` | Login and set JWT cookie |
| GET | `/api/v1/auth/me` | Get authenticated user |
| POST | `/api/v1/auth/logout` | Logout and clear cookie |

## Authentication Flow

```text
Register
   ↓
Login
   ↓
Validate credentials
   ↓
Generate JWT
   ↓
Store JWT in HttpOnly Cookie
   ↓
Request protected endpoint
   ↓
JWT middleware validates token
   ↓
Authenticated user
```
